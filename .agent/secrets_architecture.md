# Secrets Architecture: Zero-Drift Pipeline

This document defines the exact structural methodology for persisting and hydrating Google Cloud API keys across the local development environment and the native ARCore compilation phase.

## Storage Protocol
- **Location:** The primary API key (e.g., `MAPS_API_KEY`) is stored locally inside the git-ignored `frontend/android/local.properties` file.
- **Security Constraint:** This file must *never* be committed to source control. It remains physically bound to the local developer machine or injected exclusively via CI/CD Secret Managers.

## Gradle Hydration Pipeline
- **Extraction:** During the `assembleDebug` or `assembleRelease` tasks, `frontend/android/app/build.gradle.kts` parses `local.properties` or accepts variables via the `--dart-define=MAPS_API_KEY` CLI arguments.
- **Hydration:** The extracted value is assigned to a Gradle variable (`mapsApiKey`).
- **Manifest Injection:** Gradle uses the `manifestPlaceholders` map to inject this value directly into the `AndroidManifest.xml` during the final APK compilation.

## Android Manifest Binding
Both Google Maps and ARCore tracking services rely on the exact same underlying secret. The `AndroidManifest.xml` exposes dynamic bindings using the exact syntax:
- `<meta-data android:name="com.google.android.geo.API_KEY" android:value="\${MAPS_API_KEY}" />`
- `<meta-data android:name="com.google.ar.core.API_KEY" android:value="\${MAPS_API_KEY}" />`

This ensures that the sensitive API key strings never physically exist inside the raw XML file in the source repository.

## iOS ARCore Key Architecture (Sprint 6.3 Discovery)

### Root Cause
The `GoogleService-Info.plist` `API_KEY` field (auto-generated by Firebase) is restricted to Firebase-only APIs in GCP Console. GARSession (Google ARCore Geospatial) requires the **ARCore API** scope, which was missing from this key, causing `earth=errorNotAuthorized` and permanent STOPPED tracking state on iOS.

### Fix Applied
Two-layer fix:
1. **GCP Console:** Added `ARCore API` to the allowed API list on the `iOS key (auto created by Firebase)` credential.
2. **Code:** `getAPIKey()` in `ArCoreViewIOS.swift` now follows the same priority order as Android:
   - **PRIORITY 1:** `MAPS_API_KEY` from `Info.plist` (injected via `--dart-define`, same unrestricted key Android uses via `AndroidManifest.xml`)
   - **PRIORITY 2:** `GoogleService-Info.plist` `API_KEY` (Firebase key, now also has ARCore scope)
   - **PRIORITY 3:** Hardcoded fallback (unrestricted debug key)

### iOS Info.plist Binding
The `Info.plist` exposes the key via the same `--dart-define` pipeline as Android:
```
MAPS_API_KEY = $(MAPS_API_KEY)   ← Xcode build setting, injected at compile time
```

### GCP Key Restriction SOP
When creating or auditing API keys for this project, ensure the following APIs are enabled on the **iOS Firebase key**:
- All 25 Firebase APIs (default)
- `ARCore API` ← CRITICAL for iOS GARSession / Geospatial VPS

The **Android ARCore Geospatial Key** and **Unrestricted Debug Key** have no restrictions and do not require this audit step.

### Deploy Command (with keys)
```bash
LIVE_MAPS_KEY=$(gcloud secrets versions access latest --secret="MAPS_API_KEY" --project="dbomar-post-mvp")
flutter run -d <ios-device-id> \
  --dart-define=MAPS_API_KEY="$LIVE_MAPS_KEY" \
  --dart-define=IOS_MAP_ID="1bf9740a3948b2695b963ae7" \
  --dart-define=MAP_ID="1bf9740a3948b26976700a08"
```
